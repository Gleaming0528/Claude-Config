# HPC 超算平台团队周报

## 定位

这是**给老板看的团队周报**，不是技术 changelog。
老板关心三件事：**钱花得对不对、资源用得好不好、团队在做对的事**。

周报结构：
1. 关键指标（资源 + 预算 + 发布，带 Q2 目标对标）
2. 本周交付（代码自动采集 + 人工补充，翻译为业务语言）
3. 外部合作（需用户补充进展）
4. 下周计划

## 执行流程

### 第一步：采集数据

```bash
cd <repo-root>/weekly-report
python3 generate.py --dry-run 2>&1
```

自动采集维度：
- `git`: 22 个仓库本周提交（按功能域分组）
- `deploy`: deploy 仓库生产发布次数（按服务分组，含版本号）
- `gpu`: **Grafana API 实时查询**生产 Prometheus，含本周 + 上周同期数据，自动算环比
- `budget`: 预算执行数据

GPU 数据来源：Grafana → Prometheus → DCGM Exporter，口径与前端 ResourceAudit 页面完全一致。
如果 Grafana API 不可达，自动回退到 `GPU利用率周报-近8周.md` 静态数据。

### 第二步：向用户收集不可自动化的信息

用 AskQuestion 工具收集（代码采集不到的）：

**必须收集：**
1. 外部合作本周进展（阿里云/百度云/蚂蚁云/其他）
2. 本周业务协作动态（跟数据/仿真/车端团队的协调）
3. 下周重点（用户视角的优先级）

**可选收集：**
- AutoLabel / 数据处理进展
- 重大故障/事件
- 预算执行率更新（如有新数据）

如果用户已在消息中提供了这些信息，直接提取使用。

### 第三步：AI 分析与提炼

**commit 合并规则：**
1. 相同仓库+相同功能的重复提交合并为一条
2. revert + 原始提交对消，只保留最终状态
3. chore/lint 类提交不进入周报正文
4. 按业务影响力合并为 4-6 个大方向（不超过 6 个），每个方向内子功能用分号串联
5. 跨仓库联动特性合并为统一方向，不拆独立条目

**业务语言翻译（核心规则）：**
- 每个功能点回答"对业务意味着什么"，而非"技术上做了什么"
- 消灭所有需要读者"翻译"的内部技术名词（VCJob、podSpecPatch、syncStatus、AAD、CRD）
- 保留有业务共识的技术名词（Pipeline、GPU、NCCL、HF、ArgoCD）
- 用「支持」「上线」「打通」「加固」，不用「重构」「迁移」「注入」

翻译示例：
- 技术版：`动态优先级全链路落地（Label 化迁移 + VCJob 调度继承 + 前端筛选）`
- 老板版：`训练任务优先级体系上线——紧急任务可自动抢占低优先级资源，业务团队可按 P0-P3 管理训练队列`

**关键指标状态判断：**
- GPU 数据来自 Grafana API，自动包含本周和上周同期（`prev_week`）
- "状态"列不是重复数字，而是一句判断：距目标多远、变化原因、下一步
- Q2 目标线：训练利用率 75~80%、开发空间人均 GPU <1.5 卡/人

### 第四步：生成周报

输出格式严格遵循 [template.md](template.md)。

**老板 30 秒规则：**
- 老板第一眼看开头那句话 → 判断"这周状态好不好"
- 老板第二眼看关键指标表 → 哪些在轨、哪些偏了
- 这两部分写好，周报就及格了。后面是给追问准备的

**开头一句话写法：**
- 不是"本周做了什么"，是"本周状态判断"
- 包含：核心指标状态 + 本周交付核心方向（2-3 个）+ 发布数量
- 例：`训练利用率 74% 逼近 Q2 目标线，新增 64 张训练卡投产稳定，26 次生产发布覆盖优先级体系、HF 生态、多集群部署三个核心方向。`

### 第五步：写入文件

1. `weekly-report/reports/YYYY/W{nn}.md` — 精炼版周报
2. 运行 `python3 generate.py` 保存 JSON 原始数据（不覆盖 MD）

## 质量标准

1. **老板 30 秒规则**：开头一句 + 指标表格 = 老板能判断本周状态
2. commit 压缩比 >= 3:1（如 82 条 → 12 个功能要点）
3. 不允许出现 commit hash、author、邮箱
4. 不允许原样复制 commit message
5. 不允许出现内部技术名词（VCJob、podSpecPatch、CRD 等）
6. 外部合作必须有具体进展 + 下步动作，不能只写状态词
7. 关键指标"状态"列必须是判断句，不是数字复读
8. 周报总长度 60-100 行（精简比冗长好）
9. 读者是非技术管理层
