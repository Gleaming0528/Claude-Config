## 老板 30 秒规则

老板只看两眼：
1. **第一眼看开头那句话** — 判断"这周状态好不好"
2. **第二眼看关键指标表** — 哪些在轨、哪些偏了

这两部分写好，周报就及格了。后面的内容是给追问准备的。

## 关键指标"状态"列怎么写

- 达标或超标 → `达标` / `超出目标 X%`
- 接近目标 → `距目标线 X%`
- 偏离且有对策 → `{偏差}，{对策}`
- 环比上升 → `+{X}（{原因}）`
- 环比下降 → `{原因}`（不用负面词，说清原因即可）

## 本周交付翻译规则

| 技术描述 | 业务翻译 |
|----------|----------|
| Label 化迁移 + VCJob 调度继承 + 前端筛选 | 优先级体系全链路上线，业务团队可按 P0-P3 管理训练队列 |
| podSpecPatch 注入 + GPU 支持 | Pipeline 支持 GPU 算子，数据处理和模型评测可在 Pipeline 中直接使用 GPU |
| syncStatus 变更检测补全 AvailableReplicas | 推理服务上线状态实时可见 |
| SSH 密钥加密/解密统一 AAD | 密钥安全加固，防泄露 |

原则：消灭所有需要读者"翻译"的技术名词。保留有共识的（Pipeline、GPU、NCCL、HF），消灭内部的（VCJob、podSpecPatch、syncStatus、AAD、CRD）。

## 功能主题排序

按业务影响力降序：
1. 直接影响业务产出的核心能力（优先级调度、HF 生态、Pipeline GPU）
2. 生产化/稳定性/多集群
3. 资源效率（利用率提升、成本优化）
4. 数据处理（AutoLabel 等）
5. 安全合规
6. 交互体验
7. 零散修复归入末尾，不超过 1 条

## 与上周周报的衔接

1. **关键指标**自动环比（Grafana API 查上周同期数据）
2. **外部合作**承接上周"下步动作"，说明本周实际进展
3. **下周计划**不重复上周已完成项

## 合并示例

原始 7 条 commit（3 个仓库）：
```
hpc-studio-api: feat: 优先级从 annotations 迁移到 labels
hpc-studio-api: feat: AIJob 列表支持 priority 查询参数筛选
hpc-studio-api: fix: 优先级 label 同步修复
hpc-studio-api: fix: ListAIJobs 优先级过滤先查 labels 再回退
hpc-job-controller: fix: VCJob 创建时从 AIJob labels 继承 priorityClassName
hpc-ui: fix: 优先级筛选改用独立 priority 查询参数
hpc-ui: feat: 邮箱精简展示 + 优先级 label 筛选
```

合并为周报格式：
```
训练任务优先级体系上线——紧急任务可自动抢占低优先级资源，业务团队可按 P0-P3 管理训练队列，全链路打通（API→调度→前端）
```
