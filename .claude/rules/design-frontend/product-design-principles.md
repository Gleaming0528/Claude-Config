# HPC 超算平台产品设计原则

## 产品上下文

- **用户**：AI/ML 研究员、算法工程师、平台管理员
- **核心任务**：开发 → 训练 → 评估 → 部署 → 监控
- **设计方向**：Utility & Function — 工具性产品，工作比装饰重要
- **情感诉求**：效率感、掌控感、信任感
- **参考标杆**：Linear（精密信息密度）、Vercel（现代清爽）、GitHub（开发者友好）

## 功能设计三问（每个功能/页面必须回答）

1. **用户在这个页面想完成什么任务？** → 决定主要操作和信息层级
2. **完成任务的最短路径是什么？** → 消除不必要的步骤和点击
3. **出错时用户能否自行恢复？** → 错误提示必须可操作

## 信息架构原则

- **扁平化导航**：核心功能不超过两级菜单到达
- **任务驱动分组**：按用户工作流（开发→训练→部署）而非技术概念分组
- **渐进式披露**：首屏只展示必填项和高频操作，高级选项折叠
- **上下文保持**：切换页面时保持筛选条件、排序状态

## 表单设计原则

- **能不填就不填**：能推断的字段预填，能设默认的设默认
- **分步 vs 滚动**：字段 < 10 个用单页滚动 + FormSection 分区；字段 > 15 个且有步骤依赖才用分步
- **即时反馈**：格式校验 onChange，唯一性校验 onBlur，不等到提交
- **操作可逆**：删除前确认，提交后支持编辑

## 列表页设计原则

- **一眼识别状态**：状态标签 + 颜色语义，运行中/已停止/失败一目了然
- **快捷操作外露**：高频操作（启动/停止）直接放在行内，不藏在下拉菜单
- **空状态引导**：不显示「暂无数据」，显示「创建你的第一个 XXX」+ 操作按钮
- **批量能力**：支持多选 + 批量操作（删除/停止），减少重复操作

## 详情页设计原则

- **头部固定操作**：关键操作按钮 sticky，滚动时不丢失
- **Tab 分区**：按关注度排序，最常看的 Tab 放第一个
- **骨架屏加载**：首次加载用 Skeleton 而非 Spinner

## 反模式清单

- 一个页面超过 2 个主按钮 → 说明职责不清
- 用户需要「记住」上一步的选择 → 说明上下文传递断裂
- 成功/失败只有 Toast 没有后续引导 → 说明流程断裂
- 空状态只有一行灰字 → 说明没有考虑首次使用体验
- 表单提交后停在原地 → 应该跳转到结果或列表
